Задание выполнял на виртуальной машине virtual box, система Fedora Server 44 без графики. В машину заходил по ssh с мака, работал от своего пользователя evg, где нужны права root, использовал sudo. Второй терминал открывал тоже по ssh, в нём заходил под user1 через su. Подключиться по ssh мне было проще так как клавиатура mac имеет свои особенности, из — за которых непосредственно в окне virtual boх работать не удобно.
Пункт 1.1. Создал группу students командой sudo groupadd students, потом пользователя командой sudo useradd -m -u 1234 -g students -s /bin/bash user1. Ключ -g сразу делает students основной группой, поэтому отдельно добавлять пользователя user1 в группу не пришлось. Проверил через id user1, там uid=1234 и gid students. Результат видно в файлах passwd и group.
Пункт 1.1. Задал пароль через sudo passwd user1. С первого раза пароль почему-то не принялся, Fedora ругалась на качество пароля, su под user1 выдавал Authentication failure, поэтому пришлось перезадавать пароль, в истории это видно, но в конечном итоге все получилось. Смену пароля раз в 90 дней настроил командой sudo chage -M 90 user1 и проверил через sudo chage -l user1 (перед этим опечатался, chage -1). В файле shadow у user1 в поле масимального срока стоит 90.
Пункт 2.1. Нашёл все файлы с битом set-UID командой sudo find / -perm -4000 -type f. Первый раз запустил без слеша, find искал в домашней папке, переделал, техническая ошибка просто. sudo нужен, чтобы find зашёл во все каталоги. Сначала посмотрел полученный в результате список, потом вторым заходом записал в suid-files.out. Там 20 файлов: passwd, sudo, su, mount, chage и другие.
Пункт 2.2. Во втором терминале под user1 запустил passwd и оставил его ждать ввода пароля. В первом терминале выполнил ps -eo pid,ruid,euid,user,cmd и через awk отобрал процессы с реальным UID от 1000 и эффективным 0. Нашёлся passwd с RUID 1234 и EUID 0 и ещё su, через который заходил под user1. Результат в файле processes.out. 
Пункт 3.1. Взял утилиту cat и операцию чтения /etc/shadow. Файл /etc/passwd из примера читает любой пользователь, а shadow только root. Под user1 проверил, что cat /etc/shadow даёт Permission denied.
Пункт 3.2. Скопировал cat в домашнюю папку user1 командой sudo cp /usr/bin/cat /home/user1/cat, сделал владельцем root через sudo chown root:root /home/user1/cat и поставил бит set-UID командой sudo chmod u+s /home/user1/cat. Сначала chown, потом chmod, потому что chown сбрасывает бит. После этого под user1 команда ~/cat /etc/shadow показывает файл. Права и владельца видно в stat.out, там 4755 и root. Обычный ls -l от evg в /home/user1 не пускает, папка 700, поэтому в истории ls -l повторил с sudo.
Пункт 4.1. Взял утилиту chgrp и операцию смены группы своего файла на группу, в которой пользователь не состоит. Под user1 создал ~/report.txt и выполнил chgrp wheel ~/report.txt, получил Operation not permitted.
Пункт 4.2. Скопировал chgrp в /home/user1/chgrp, отдал файл самому user1 командой sudo chown user1:students /home/user1/chgrp, чтобы root тут вообще не участвовал, и выдал одну привилегию: sudo setcap cap_chown+ep /home/user1/chgrp. После этого под user1 ~/chgrp wheel ~/report.txt сработал, ls -l показал группу wheel. Привилегию видно в getcap.out, в stat.out у файла обычные права 0755 без set-UID и владелец user1.
Пункт 5. Через sudo visudo добавил в /etc/sudoers строку user1 ALL=(root) /usr/bin/date -s *, /usr/bin/timedatectl set-time *. Аргументы ограничил специально, руководствуясь принципом передачи минимально возможного для задачи количества привелегий: по заданию была разрешена только установка времени, а не вся timedatectl, иначе user1 мог бы поменять часовой пояс или выключить синхронизацию. С первого раза строка была записана мной с сохранением  # в начале, vi подхватил его от предыдущей строки, так как я с vi раньше особо не работал — пропустил этот момент поэтому в истории visudo два раза. Проверил через sudo -l -U user1, правило видно. Под user1 sudo date -s сработал, а sudo timedatectl set-timezone UTC и sudo timedatectl set-ntp false отказали. То есть моя задумка про ограничение привелегий сработала и наверное так правильно, хотя я не знаю, может сама постановка задачи и не подразумевала такие действия по ограничению. После проверки вернул время через sudo chronyc makestep. Результат в файле sudoers.
